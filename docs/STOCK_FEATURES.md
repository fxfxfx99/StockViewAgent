# 个股特征库

在 **关注个股 → 个股特征库** 查看当前股票的特征、来源、事件传导路径、缺口、历史行情反应和版本变化。**更新特征** 从本机已采集资料重新构建，不调用大模型，也不隐式抓取付费数据。

## 每股独立的结构化证据

`stock_feature_engine` 读取公司基础与财务记录、经营讨论、公司资料缓存、日线及明确关联该公司的新闻。每条特征包含稳定标识、类别、数值或原文、单位、报告期、来源标识、引用和证据状态。原始编码财务字段没有字段字典或单位时保持未知，不将数值猜成某种比率。

业务构成、产品产能、地区币种、客户需求、供应链、成本、财务约束及市场行为分别记录覆盖情况。直接披露、规则定位的候选片段和行情统计分别标识。没有材料的股票也会进入更新队列，其页面保留缺口，不生成虚构特征。

事件因子连接到该股具体特征与来源。例如，只有存在采购成本披露，才能建立投入品价格的条件性传导；只有有跨境业务材料，才建立贸易和汇率的待验证关系。每个关系记录经营传导、兑现条件、抵消因素和后续观察项。行业标签本身不能证明业务暴露，经营影响也不直接等于股价涨跌。

## 每周更新与版本

后端开启 `ENABLE_SCHEDULER` 和 `ENABLE_STOCK_FEATURES`（均默认开启）后，维护本地全市场名单、所有账户自选及访问过的股票。首次建立立即进入队列，以后每周六北京时间 **09:00** 到期，每批最多 10 只；后端停机或电脑休眠时暂停，恢复运行后补跑。

每股使用 SQLite 租约，多个进程不能重复领取同一任务。失败保留上次成功版本，一小时后重试；手动刷新有 30 秒冷却。内存压力或剩余磁盘不足 1 GiB 时暂缓批次。周更新重建特征时，原始来源本身可能仍未更新，页面同时保留资料时间和本次构建时间。

数据库 `backend/data/stock_features.sqlite3` 随 `STOCKVIEW_DATA_DIR` 搬迁。版本不可覆盖，保留新增、变更、移除的特征和构建时可见证据；内容未变时复用版本、另存轻量检查记录，避免每周复制全市场的相同原文。历史查询同时检查资料截至时间与实际创建时间，检查记录也按历史时点过滤。安装后构建的新库不能倒填到旧新闻的过去时点。

## 新闻解读如何使用

1. 按事件发布时间读取该股当时已经存在的版本，未知事件时间或没有历史版本则明确缺失。
2. 从事件文本匹配该股已经保存的因子，保留实际命中词、相关特征及来源。
3. 将匹配关系交给分析模型，要求结构化 `feature_impacts`：具体暴露、经营影响、估值影响、兑现条件、抵消因素、观察项和引用。
4. 程序校验股票、因子、特征、版本与引用的对应关系。不能引用另一只股票的材料，也不能输出库中不存在的因子。无匹配时不能把未知写成“没有影响”。
5. 结果保存特征版本与内容签名。历史时点的特征上下文改变后，旧结果重新进入待解读；事件以后出现的新版本不会反复触发旧新闻重算。替换结果时保留旧分析。

约束检验负责检查数据绑定与引用完整性；业务推断的正确性仍需后续披露和人工复核。关系目前是基于材料的条件性假设，尚未经过因果识别或样本外预测验证。

## 行情与历史事件反应

资料足够时计算近 20 交易日收益、近 60 交易日年化波动率和相对基准 Beta。直接关联新闻可观察 1、5、20 个后续交易日的个股收益、基准收益及两者之差，展示窗口、样本数和原始事件。

这些统计以事件日或此前收盘为起点，不衡量事件日即时反应。缺少同期基准时不计算超额收益；缺少足够后续日线时不补数。统计存在事件选择、同日其他信息、重叠窗口和复权口径等限制，属于描述性观察，不能解释成该因子的因果作用或未来涨跌概率。

## 接口

| 接口 | 行为 |
|---|---|
| `GET /api/stocks/{symbol}/features` | 当前版本、历史摘要、更新状态及下次到期时间 |
| `POST /api/stocks/{symbol}/features/refresh` | 根据已采集本地资料重建，返回更新或冷却状态 |
| `GET /api/stocks/{symbol}/features/history?limit=12` | 版本摘要，最多 52 个 |
| `GET /api/stocks/{symbol}/features/history?version_id=…` | 指定股票的完整历史版本 |

接口沿用应用登录策略；公共特征库不读取私人研究档案、个人监控报告或模型密钥。
