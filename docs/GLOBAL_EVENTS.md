# 全球经济金融事件日历与 Agent 检索

从顶部 **工具 → 经济日历**（`/calendar`）进入。月历支持地区、类别、重要性、状态和关键词筛选；点击日期查看议程，再点击「查看详情」查看原始来源链接、采集时间和历史修订。精确时间统一显示北京时间；来源只给日期时保留来源日期与时区，标记「时间待定」。重要性为本地分类，不是官方预测或买卖信号。

## 来源与监控

| 来源 | 覆盖 | 限制 |
|---|---|---|
| [美联储 FOMC](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm) | 货币政策会议结束日、已发布声明入口 | 未给具体时刻时按日期显示，不推断政策结果数值 |
| [欧洲央行](https://www.ecb.europa.eu/press/calendars/mgcgc/html/index.en.html) | 货币政策会议与新闻发布会 | 日程不提供市场预期或决议数值 |
| [日本银行](https://www.boj.or.jp/en/mopo/mpmsche_minu/index.htm) | 政策会议、展望报告、意见摘要、纪要 | 仅在官方说明时采用确切时刻 |
| [中国国家统计局](https://www.stats.gov.cn/sj/fbrc/bnxxfb/) | CPI/PPI、PMI、国民经济、工业、社零、投资等年度发布计划 | 覆盖官方已公布年度，次年尚未发布时不补造日程 |
| [美国劳工统计局](https://www.bls.gov/schedule/news_release/bls.ics) | 就业与 CPI/PPI 等发布安排 | 部分网络返回 HTTP 403，页面如实显示失败并保留旧数据 |

这是一组跨美、欧、中、日的重大官方日程来源，不代表覆盖所有国家、所有临时事件或实时财经快讯。当前日历源通常不提供市场一致预期、前值和公布值；这些字段显示「—」，不能将到达预定时刻推断成已公布。只有明确发布链接或结果证据才记为已公布，过期但未经证实的计划显示「日程已过·结果待核验」。

默认由 [数据中心](DATA_CENTER.md) 的中央采集 worker 统一调度 `economic_calendar`，API 启动约 10 秒后开始轮询。自动监控需 `ENABLE_DATA_COLLECTION=true`，且数据中心的自动采集和日历来源开关均开启；不依赖 `ENABLE_SCHEDULER`。日历任务默认每 60 分钟到期，每个官方来源最多每小时自动请求一次；实际执行还受中央队列、每日逻辑任务额度与最低剩余磁盘空间约束，不保证每个整点完成。

在数据中心暂停自动采集或关闭日历来源，会取消尚未执行的对应自动任务，不另启备用调度。若通过环境变量设 `ENABLE_DATA_COLLECTION=false` 并重启，API 在 `ENABLE_SCHEDULER=true` 时回退到原有独立日历监控；此时日历备用监控不使用中央队列预算。`ENABLE_SCHEDULER=false` 只停止备用调度，不影响已开启的中央采集。日历页面的「刷新事件」仍可直接手动刷新，有 60 秒来源冷却；它与数据中心的手动排队任务是两个入口。

监控只读取固定官方地址，不需要行情 token 或模型 Key；采集本身不调用模型。多进程共享刷新锁，成功来源独立入库；HTTP/格式错误只更新状态，不清空旧记录。浏览器每分钟读取本地状态，不直接抓取上游。关闭服务后不继续运行，重新启动会按所启用的调度检查日程。

每次请求按当前日期保留前 14 天至后 370 天内的官方记录，长期运行会持续积累历史。页面能翻看更早月份，但新安装实例没有凭空补齐的历史证据。服务运行期间的自动采集会逐步填充日历；首次使用也可点击「刷新事件」。

部分官方 HTML 日历没有稳定事件编号；改期或删除条目时，系统可能保留先前观察到的安排。未再次出现不等于取消，新旧日期不能自动视为同一事件，请以官方最新日程核验。有稳定来源编号的事件保留同一事件下的修订；没有编号时保守保留独立记录，避免猜测两次会议是同一件事。

## 真正进入解读的 RAG

数据存入 `STOCKVIEW_DATA_DIR/economic_events.sqlite3`，包含不可变事件修订、逐修订文本分块、SQLite FTS5 索引、来源采集状态和账户配置。语料来自已经采集的日程记录，不是提示词内写死的宏观知识。重复采集相同内容不制造新修订，来源内容变化会生成新版本；每条引用保留 `event:<事件ID>:<修订ID>`。

检索先限制历史可见版本，再按日期窗口、地区、类别和重要性筛选，以中英文词项与 BM25 选取相关片段。为避免未来文档影响旧排名，BM25 的语料统计也只使用截止时点可见的版本。公司名没有直接命中宏观标题时，可在设定窗口内补充重大日程，并明确标注匹配原因。当前实现是结构化过滤与全文检索 RAG，无需另配 embeddings 服务；没有把上传资料混入公共事件库。

点击 **Agent 事件检索** 配置当前账户的总开关、四类 Agent 开关、回看/前瞻天数、最低重要性、地区、类别和最多检索条数。该配置决定实际检索结果，不会只修改提示词；公共源采集仍共享进行。账户间不共享个人检索配置。

| 调用链 | 事件证据如何使用 |
|---|---|
| 新闻解读 | 按新闻发布时间检索，加入 `context.evidence_sources` 的 `E*` 可引用事实；不能替代当前新闻 `N0` |
| 多策略观点与选股 Agent | 加入信号资料、详细分析、风险观察项和引用；选股继承多策略证据，不因日程存在而修改规则评分或置信度 |
| 量化研究实验室 | 真正的候选生成请求按开发期结束时间检索，写入原有请求审计；不读取保留测试期之后的事件版本，也不新增未支持的交易因子 |
| K 线、市场研判与问答 | 检索证据进入实际模型输入；手动及定时 K 线解读历史保留当次事件版本，按账户隔离 |

所有 Agent 检索只读本地库，不在推理期间发起日历采集。失败时返回明确的证据缺失说明，保留原有分析流程。事件传导需要结合行业和主营业务解释，日程、前值、预期与公布值须分别表述，不因重大事件自动制造看多/看空结论。

## 历史可见性

`scheduled_at` 是计划时间，`observed_at` 是本机第一次观察到这个修订的时间，两者含义不同。历史查询先选 `observed_at <= as_of` 的版本，再按事件选择最后一个可见修订。后来补采的老日程、后续公布值和改期不会倒流进入早期分析；这也意味着新安装实例对很早的历史时点可能检索不到任何事件。

日期形式的策略分析节点按上海当日结束处理；量化开发期已有 Unix 秒上界保持精确时间。时点筛选不证明提供者历史公告时间，也不替代研究实验室的严格数据检查。当前源健康状态不会写入历史时点的事实上下文。

## API、数据与部署

以下接口均需按部署设置完成身份认证，且读取不会触发采集：

| 接口 | 用途 |
|---|---|
| `GET /api/events/calendar` | `start/end` 为上海日期，单次最长 366 天；可带 `region/category/min_importance/q` |
| `POST /api/events/refresh` | 手动刷新固定来源，返回逐来源结果 |
| `GET /api/events/{id}` | 事件及不可变修订历史 |
| `GET/PATCH /api/events/config` | 当前账户的实际 Agent 检索配置 |
| `GET /api/events/search` | 用 `q`、`agent`、可选带时区 ISO `as_of` 预览实际检索证据 |

数据库跟随统一数据目录迁移，已纳入资产分类。备份时按项目的停机迁移流程处理 SQLite WAL，勿只拷贝正在写入的主库。当前公开试用网关保持其既有接口白名单，新日历页面与控制接口只在本地/常规部署开放。
