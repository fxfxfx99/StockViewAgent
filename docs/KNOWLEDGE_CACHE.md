# 本地知识库、提示词版本与更新跟踪

从 **数据中心 → 知识与提示词** 管理个股特征、新闻相关性知识和新闻分析提示词。管理页面与接口要求管理员身份；本地免登录模式使用默认管理员。浏览、同步本地资料和调整提示词不调用模型。提示词变化后，需要分析的新闻由原有新闻分析流程重新判断。

## 本地目录与权威来源

目录跟随 `STOCKVIEW_DATA_DIR`，默认位于 `backend/data/knowledge_cache/`。

```text
backend/data/
├── stock_features.sqlite3                # 个股特征的权威历史、检查与更新状态
├── news.db                               # 新闻原文、分析及分析历史
├── prompt_overrides.json                 # 旧版覆盖文件；首次白名单迁移后保留原件
└── knowledge_cache/
    ├── README.md                         # 目录自身的维护说明
    ├── registry.sqlite3                  # 不可变版本、当前启用版本及审计事件
    ├── registry.lock                     # 跨进程读写锁
    ├── objects/sha256/<前两位>/<哈希>.json.gz
    ├── current/
    │   ├── stock_features/<股票代码>.json
    │   ├── news_relevance/<股票代码>.json
    │   └── prompts/<提示词标识>.json
    └── manifests/
        ├── stock_features/<股票代码>.json
        ├── news_relevance/<股票代码>.json
        └── prompts/<提示词标识>.json
```

| 数据 | 权威来源 | 当前文件的作用 |
|---|---|---|
| 个股特征 | `stock_features.sqlite3` 的不可变历史版本 | `current/stock_features/` 是管理与阅读镜像；重建不改变原特征历史 |
| 新闻相关性知识 | `registry.sqlite3` 的版本指针与 `objects/` 的内容 | `current/news_relevance/` 是该股当前启用知识的可读投影 |
| 新闻分析提示词 | `registry.sqlite3` 的启用状态与 `objects/` 的版本正文 | `current/prompts/` 是有效稿、源码默认稿和迁移记录的可读投影 |
| 来源、哈希和当前版本 | 登记库中的版本与事件 | `manifests/` 便于对账，不是另外一份可编辑配置 |

`objects/` 按正文的 SHA-256 去重，JSON 使用 gzip 压缩。登记库保存版本元数据，不再存一份完整正文；`current/` 保留易读 JSON。相同内容再次同步不会增加内容版本，会记录检查事件。版本和操作记录都保留，不自动过期删除。

个股特征镜像是紧凑视图，保留实际特征值、引用、版本和覆盖情况，来源只保留有界摘要。完整来源正文与逐事件行情样本继续保存在 `stock_features.sqlite3` 对应的原始特征版本中，管理镜像不替代研究所需的原始证据。

**名称里的 cache 不表示整个目录可以清空。** `registry.sqlite3` 与 `objects/` 包含提示词的用户编辑、回滚和知识历史，属于持久资料。`current/` 与 `manifests/` 可以从权威对象修复；它们不是导入入口，手工修改不会成为启用版本。正常管理应使用页面、受限接口或 CLI。

## 每股相关性知识如何使用

每只股票独立保存：

- 公司简称、全名及来源：用户补充、已缓存公司资料或 A 股名单。
- 用户明确配置的该股新闻关键词；只读取 `integrations.json` 的公开新闻关键词字段。
- 来自个股特征的产品、成本、地区等业务对象、因素、特征版本、来源引用及原始状态。
- 区分主体标识、来源披露状态与尚需核实的候选联系的规则。

实际新闻匹配读取该库中的别名和用户关键词，更新关键词后无需重启。行业标签不会自动关联同一行业的所有股票；业务对象保留为分析上下文中的候选联系，不单凭对象名称把新闻加入股票列表。用户关键词也不等于已核实的公司暴露。

模型收到的业务对象必须对应 `stock_features` 中本次选取的同股、同历史版本特征。当前补充的知识不会倒填更早事件的经济暴露。已有历史特征仍通过原数据库按事件时点读取，缺失时明确说明缺口。

## 同步与资源边界

个股特征仍按原计划在 **每周六北京时间 09:00** 分批检查与更新，详见 [个股特征库](STOCK_FEATURES.md)。成功更新后的特征同步至本地管理目录，并更新对应股票的相关性知识。后台另执行每日本地核对，补齐已有特征镜像和相关性知识：首次启动可立即执行，后续按 86,400 秒间隔核对，并非固定在某个整点。停机期间不运行，恢复后继续未完成工作。

`ENABLE_KNOWLEDGE_CACHE` 默认开启，控制本地知识维护 worker；自动核对另依赖 `ENABLE_SCHEDULER`。关闭定时调度后，只要本地知识 worker 仍开启，管理员手动提交的同步队列仍可执行。修改环境变量需要重启后端。

本地核对读取已有资料，不联网补造业务信息，不调用大模型，也不保证缺失资料会因此变为已知。全市场任务分批执行；管理页显示实际完成、待处理与失败状态。需要补充来源时，仍应使用公司资料、公告或特征库原有采集流程。

新闻归档判断旧结果能否复用时，只检查三类提示词的版本状态、单股知识标识以及单股特征标识，不扫描全市场或读取完整特征正文。提示词版本按登记库变更标识缓存；来源文件的大小和时间状态变化后才重新读取。相关性正文的进程内缓存最多保留 256 股，持久正文保存在本地目录。

## 提示词编辑、默认升级与回滚

当前管理三类新闻分析提示词：

| 标识 | 用途 | 默认源文件 |
|---|---|---|
| `system_prompt` | 系统指令 | `backend/app/prompts/system_prompt.md` |
| `news_relevance` | 逐股相关新闻判断 | `backend/app/prompts/news_relevance.md` |
| `stock_impact_analysis` | 条件性经营与股价影响分析 | `backend/app/prompts/stock_impact_analysis.md` |

正文必须非空且不超过 20,000 个字符。保存记录操作者、原因、时间、版本和哈希。更新时提交编辑起点的版本标识；如果另一位管理员已保存新版本，后端拒绝过时编辑，页面应重新加载并比较后再保存，避免覆盖他人修改。

源码默认稿分别记录在 `default.<标识>`。应用升级修改默认 Markdown 时，默认稿会产生可追踪的新版本；仍在使用默认模式的有效稿跟随升级。自定义稿与用户回滚稿保持启用，不被源码更新替换。**恢复默认**采用操作时的最新源码默认稿。

**回滚**从选定历史版本恢复文本，创建新的审计版本，并记录 `restored_from`。历史版本本身不修改，回滚稿也不会被下一次源码默认升级覆盖。只有上述三个有效标识可以编辑；默认稿和 `migration.legacy` 是内部记录。

首次初始化时读取旧 `prompt_overrides.json` 中的 `prompts` 对象，只迁移三类白名单正文。未知键不会成为可执行提示词，也不会复制未知键的正文；原文件保留。迁移完成后以登记库为准，后续请通过管理入口修改，继续编辑旧文件不会覆盖已迁移的版本。旧文件 JSON 损坏、已知正文为空或超长时，迁移明确失败，不默默放弃原有自定义内容。

## 分析绑定与历史保留

一次新闻判断先冻结三类提示词和各股票的知识版本，相关性判断与影响分析使用同一组快照。中途有人编辑提示词或关键词，新稿从后续判断开始生效，当前两阶段不会混用。

分析结果保存 `prompt_versions`、`news_relevance_version`、`news_relevance_hash`、`analysis_logic_signature`，以及原有个股特征版本与签名。每类提示词同时保存登记库内容哈希和实际纯文本的 `text_hash`，可检查实际使用了哪一稿。

提示词、该股相关性知识或判断规则变化后，旧结果不再被当作当前逻辑的有效缓存。重新判断保存新结果，并保留之前的分析历史；不能把重新分析的失败结果伪装成已更新的成功判断。旧版尚无逻辑签名的结果需要按新规则重新核对。是否立即开始模型分析仍受模型配置、新闻日期及原有任务流程控制。

## CLI 与排查

CLI 位于 `backend/scripts/knowledge_cache.py`，在 `backend/` 目录使用项目 Python 环境运行。`status` 查看本地同步与容量状态；`rebuild` 重建允许的本地镜像和知识；`inspect` 按类型和标识检查具体文档。用 `--help` 查看当前支持的参数。

```sh
cd backend
.venv/bin/python scripts/knowledge_cache.py status
.venv/bin/python scripts/knowledge_cache.py rebuild --scope all
.venv/bin/python scripts/knowledge_cache.py rebuild --scope relevance --symbol 600519.SS
.venv/bin/python scripts/knowledge_cache.py inspect news_relevance 600519.SS
.venv/bin/python scripts/knowledge_cache.py inspect prompts news_relevance --revision-id <版本ID>
```

`rebuild --scope` 接受 `all`、`stocks`、`relevance`、`prompts`；`--symbol` 限定单股。CLI 提交受限同步任务，并执行到本次任务完成，已有其他任务可能先被处理。没有股票范围限制时遵循本地已登记的股票集合。

重建不意味着清库，不删除旧特征、历史提示词或分析记录。管理员排查时应先检查最后成功同步、失败原因、有效版本和来源版本，再决定是否重建。CLI 与应用使用同一个 `STOCKVIEW_DATA_DIR`；启动命令指定不同目录时看到的资料也会不同。

## 损坏处理、保护与备份

缺失或被修改的 `current/`、`manifests/` 在读取时核对并从已验证的权威对象修复；不会把手工文件变更自动导入。权威对象的压缩数据、正文哈希或登记库损坏会明确报错，不能悄悄覆盖不可变对象。符号链接、硬链接或越界路径受到拒绝。

公司资料或新闻关键词来源 JSON 损坏、已知关键词配置无效时，相关性知识同步保留已有版本并报告错误，不把读取失败解释成删除已有别名或关键词。修复可信来源后重新同步；涉及权威历史损坏时，先恢复可信备份。

知识构建只选择公司公开资料、用户明确的该股关键词和特征来源。它不复制完整集成配置，不导入 API Key、Cookie、登录信息、账户资料或私人研究内容。管理正文仍仅对管理员开放；审计记录保留操作身份。

备份时先停止后台写入，连同 `knowledge_cache/`、原始 `stock_features.sqlite3` 和新闻数据库一起备份。运行中备份必须正确处理 SQLite WAL，不能只复制主数据库文件。详见 [本地数据目录与搬迁](LOCAL_SETUP.md#本地数据目录与搬迁)。本目录不属于普通缓存过期回收白名单，容量增长应通过检查统计、完整备份和人工维护处理。
