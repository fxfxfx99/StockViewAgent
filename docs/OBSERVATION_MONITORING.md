# 观察、监控与复盘

入口是顶部 **监控**（`/monitor`），以个股和股票列表为主要对象。用户定义要持续了解的问题，后台用当前账户配置的模型检查本地证据，保存报告并在有意义的变化时提示。它与 **关注个股**（`/`）、**研究**（`/research`）组成主工作流；原量化实验室在 `/lab`，与新研究使用不同的任务和预算。往返步骤见 [研究工作台](INVESTMENT_WORKSPACE.md)。

## 开始使用

1. 点击 **配置观察模型**，选择供应商并保存 API Key；自定义供应商需填写兼容 Chat Completions 的 API Base 与模型名称。
2. 点击 **验证已保存连接**。这是一次实际小请求，可能产生供应商费用，也计入本功能每日额度。验证通过后可创建计划。Key、接口地址或模型改变后需重新验证。
3. 新建计划，默认选择个股；也可选择股票列表，从当前账户自选股中选择导入或输入 1–20 个代码。仍可选择五个 A 股大盘指数或关键词主题；主题至少填写一个关键词。
4. 填写自己的目标、重点观察条件、原判断失效条件、来源、检查频率和复盘日期。来源可选新闻、行情、技术指标、策略观点、公司公告、论坛讨论；默认新闻与行情。默认每 6 小时检查一次，30 天后复盘；也可选择每小时或每天。
5. 查看报告的条件核对、变化、风险、下一步和原始证据。到期后查看 AI 复盘，再记录人工的继续、修改或关闭决定及理由。

保存观察模型使用独立入口，不额外提交研究任务或加入示例自选。模型凭据与当前账户已有配置共用，修改它会影响该账户其它模型功能；已启用的自动研究仍按自己的设置和额度使用更新后的凭据。读取页面、计划、报告和提醒不调用模型。

## 股票列表

股票列表保存明确的成员代码，规范化并去重。导入自选只读取当前账户名单；后续增删自选不会自动改变计划，需编辑计划成员后保存。这样历史观察和复盘能够还原当时的名单。

一次列表检查使用一个任务，最多发出一次模型请求；报告包含整体判断与逐股观察，每只股票都有结论、简述和本股证据。没有新鲜资料的成员显示证据不足，不使用另一只股票的资料替代。列表越长，每股可纳入的证据越少，覆盖情况会显示实际纳入条数、资料新鲜度及截取情况。

任一成员缺少新鲜证据时，整体结论保守显示证据不足，其余成员有依据的逐股结论仍保留。列表关键词作为模型关注重点；资料匹配依据对应股票的代码和公司名称，避免将泛主题新闻当作每家公司的事实。

新增、删除成员会形成计划新版本，取消未执行的旧任务，并重新建立判断基线。已经发出的旧任务保留当时名单和结果，不覆盖新版本。逐股结论变化也会产生站内提醒；仅文字改写或成员顺序改变不会触发变化提醒。

## 后台行为与提醒

`ENABLE_MONITORING=true` 默认在 API 进程中开启独立 worker，约每 15 秒检查到期队列。它独立于 `ENABLE_SCHEDULER`、研究 worker 和中央公共数据采集；没有用户创建的启用计划时不调用模型。关闭浏览器页面不影响执行，电脑或 API 服务停止期间不会检查；恢复后按持久化队列处理。

每个计划同时最多一个排队或运行任务。默认每次成功完成后按所选间隔安排下一次。复盘日期按北京时间计算，到期产生站内提醒，并在下一次到期检查时优先生成 AI 复盘；同一复盘日期成功完成后不反复生成到期复盘。点击 **生成AI复盘** 可主动重新评估。

观察输入未变化时复用原报告，并标明原报告日期，不新增模型请求。没有可用事实时保存资料不足报告，不调用模型。结论或条件状态变化、资料新增或修订、到期复盘和首次连续失败产生站内提醒；同样的错误、仅措辞变化、缓存读取时间变化或材料自然变旧不持续刷提醒。资料变化提醒只表示发现新资料，不表示原投资判断已经得到证实。不发送邮件或聊天消息。

提醒的 **已读** 与 **处理记录** 分开。已查看、忽略、转入研究需保存处理理由和来源快照；标为已读不会自动标为已处理。打开触发任务可查看当时对象、检查日期、证据与报告，不能把检查日期当成事件披露时间。转入研究使用同账户成功任务的证据，在同一档案内幂等导入；导入本身不调用研究模型，生成更新须明确提交。

从研究报告的下一步观察创建计划，会保留 `research_link` 来源档案、报告及条目序号。草稿仍须用户确认后保存；研究生成或采用不自动开启监控。研究报告与监控对象必须一致，后续更换对象不把旧研究归因给新对象，历史版本保留原来源。

可暂停单个计划或账户全部监控。暂停会取消排队任务并停止新任务；已发出的请求可能仍完成，结果作为当时计划的历史保存，不覆盖新版本。关闭计划保留历史。移除密钥或停用 worker 后，仍可读取已有报告和记录人工复盘。

人工复盘记录与模型判断分别保存。修改计划有版本检查，避免多人或多窗口覆盖；报告附运行时的计划快照。模型只生成研究文字与条件判断，不能修改人工决定或执行交易。

## 数据范围与解释

| 来源 | 本功能读取范围 |
|---|---|
| 个股／大盘日 K | 本地有效日线缓存，单股／指数最近 10 条，列表每股优先最近 3 条并按输入容量截取；五个指数为上证、深成、创业板、沪深300、上证50 |
| 本地新闻 | 最近归档内容版本中匹配代码、公司名或关键词的标题与公开摘要 |
| 海外新闻 | 已归档的匹配标题、公开摘要、来源和原文链接 |
| 公共资料 | 已采集记录中的匹配资料、统计期与引用版本；遵守数据中心的公共资料 RAG 开关 |
| 经济日历 | 已归档的匹配日程及来源；预定事件与公布结果明确区分 |
| 技术指标 `indicators` | 根据本地有效日 K 计算 MA5、MA20、MACD 和 RSI24，保留计算时点与输入边界；不是新的远端行情 |
| 策略观点 `strategy` | 当前账户已经保存的策略记录；属于观点，不触发新策略分析 |
| 公司公告 `announcements` | 本地财报公告目录及公司公告缓存片段；目录记录不代表已读取财报全文 |
| 论坛讨论 `forum` | 当前账户已经保存的雪球讨论；属于未核实观点，不在检查时抓取或筛选新讨论 |

`channels` 可填 `news`、`price`、`indicators`、`strategy`、`announcements`、`forum`，至少一项、最多六项，默认 `news` 与 `price`。`news` 包括表中的本地新闻、海外新闻、公共资料与日历；`price` 对应日 K。缺少资料或对象不支持所选来源时显示覆盖缺口，不伪造内容。股票列表逐股读取这些来源；指数支持行情与技术指标，主题主要按关键词检索新闻类资料。

论坛和策略证据明确标记为观点，不能单独支持经营事实或确定条件；技术指标标记为计算结果，公告目录标记为目录信息。新研究可使用相同本地来源，但采用独立的研究报告结构和额度；研究私人上传材料不会自动成为监控的公共来源。

报告只使用当次列出的有上限的匹配证据，不保证覆盖所有相关报道。运行分析时不会临时抓取远端新闻或行情；需保持公共数据采集正常运行，并核对各来源最近成功时间。海外关键词建议包含来源实际使用的语言，例如中英文公司名。

创建个股或股票列表观察计划不会自动改写自选或采集名单。需要持续更新各股行情时，先将它们加入自选或数据中心的采集股票范围；已有新闻按代码、名称和关键词匹配，列表的逐股证据须匹配对应股票。

此处的主题计划按用户填写的关键词读取已归档日历；经济日历页面现有的新闻／策略等 Agent 检索范围配置不控制观察计划。

新闻默认以 7 天、日 K 以 14 天作为新鲜度边界。缺少可靠发布时间、未来时间或超期资料会标记；统计期与采集时间不能冒充发布时间。经济日历目前没有精确公布时间，日程或公布值仅作带日期限制的参考，不能单独支持“条件满足”。只有存在引用且引用为新鲜证据，才允许确定的条件状态；陈旧或缺失资料会降低为不确定。

这些检查约束引用和时间，不保证模型对事实的理解正确。应根据报告中的原文与证据核对结论。既有 `/today` 继续提供原来的本地变化浏览与人工关注判断，不要求使用此模型工作流。

## 请求额度与失败恢复

- 每账户默认每日 **12 次**模型请求，可设为 1–100 次，北京时间零点换日。该额度只控制观察功能，独立于研究实验室额度。
- 连接验证、定时观察、手动观察和 AI 复盘共用此额度；失败请求也计入。配置未改变且已验证时重复点击验证复用成功状态。
- 单次分析输入最多约 24,000 字符，股票列表按成员分配输入空间。单股、指数和主题输出最多请求 1,800 tokens；列表根据成员数提高，最多 4,000 tokens。额度是请求次数上限，不是金额保证，实际费用由供应商定价与使用量决定。
- 每次任务只发一次请求，不在同一任务内部切换密钥、供应商或自动重试。失败后记录原因，按计划间隔和退避安排下一次检查。验证失败后短暂冷却，避免重复点击。
- 达到每日上限后任务等额度恢复；不会绕过上限。暂停期间仍可主动验证新配置，验证同样计入额度。
- 后台通过进程锁、任务租约与原子计数防止重复执行。重启时未发送的任务可恢复；已发送但无法确认结果的任务标为 `unknown_result`，不重发同一请求。后续新周期仍可正常检查。

## 保存与接口

所有数据随 `STOCKVIEW_DATA_DIR` 存在 `monitoring.sqlite3`：计划及版本、任务、报告与证据快照、人工复盘、提醒、不可变处理历史及每日请求计数。它属于长期数据，不纳入展示缓存清理；随整个数据目录备份和迁移。账户之间不能读取彼此的计划和报告。公开试用网关不开放此页面或接口。

接口均以 `/api/monitoring` 开头，使用当前账户身份：

| 接口 | 用途 |
|---|---|
| `GET /overview` | 模型验证、后台、额度、计划与提醒 |
| `PUT /model`、`POST /model/verify` | 保存账户模型、显式连接验证 |
| `PATCH /config` | 账户暂停／启用、每日请求上限 |
| `POST /plans` | 新建计划 |
| `GET /plans/{id}`、`PATCH /plans/{id}` | 读取详情与带 revision 的修改 |
| `POST /plans/{id}/runs` | 提交 observe 或 review 任务 |
| `POST /plans/{id}/reviews` | 保存带 revision 的人工复盘 |
| `PATCH /notifications/{id}` | 更新 is_read |
| `GET /runs/{id}/context` | 查看原任务对象、检查日期、报告和冻结证据 |
| `POST /notifications/{id}/handling` | 保存已查看、忽略或转入研究的处理理由与来源快照 |

列表计划使用 `target_type="stock_list"`、`target_code=""` 与 `target_symbols=["600519.SS","000001.SZ"]`。非列表计划的 `target_symbols` 为空数组；切换对象类型需同时更新代码与成员字段。旧计划缺少该字段时按空数组读取，不改写历史快照。

`ENABLE_MONITORING=false` 并重启后不执行观察或 AI 复盘队列，仍可阅读历史、记录人工复盘与显式验证模型配置。配置错误、验证失败、额度耗尽和版本冲突均显示原因，已有成功报告继续保留。
